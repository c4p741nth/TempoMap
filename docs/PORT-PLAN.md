# Port plan: C# engine (Core + Cli)

Goal: reimplement the analysis engine in C# (.NET 10). It must reproduce the original
`TimingAnlyz 0.32.4.exe` output exactly: 45/45 parity runs. The engine becomes the base for the
Avalonia editor. A GUI and multi-BPM are **out of scope** for this plan.

This document is self-contained. It is written so that any executor (another model, Codex, a
person) can carry it out without the conversation that produced it.

## Numeric rules (each one matters for exact parity)

1. **Use `double` everywhere.** The reference is float64 and matches the original at printed precision.
2. **Biquad** = SciPy `sosfilt`, which is transposed direct form II, one section after another. Per section, `b = [g, g*n1, g*n2]` and `a = [1, d1, d2]`:
   `y = b0*x + z1;  z1 = b1*x - a1*y + z2;  z2 = b2*x - a2*y`. State starts at 0.
3. **`round(x)` in the spec means `Math.Floor(x + 0.5)`.** Never use `Math.Round`, which rounds half to even.
4. **`math.fmod` is the C# `%` operator on doubles** (truncated remainder). It is *not* `Math.IEEERemainder`.
5. **`np.argmax`** returns the first index of the maximum. Use strict `>` while scanning.
6. **Lengths** use `(int)Math.Ceiling(...)`. Floors use `(int)Math.Floor(...)`. Keep the exact expressions, e.g. the resample index `floor(i * (1.0 / ratio) + 0.5)` with `ratio = 1000.0 / rate`.
7. **Autocorrelation**:
   - `nfft = 1 << ceil(log2(n + lags - 0.5))`
   - `acf = real(IFFT(|FFT(x)|^2))[0..lags)`, unnormalized, i.e. `acf[l] = Σ x[i]·x[i+l]`
   - write your own iterative radix-2 complex FFT in double
8. **Envelope tail**:
   - `d[m-1] = -fwd[m-2]`
   - `d[i] = bwdRev[m-i-2] - fwd[i-1]` for `1 <= i <= m-2`
   - `d[0] = bwdRev[m-2]`
   - `bwdRev` is the post filter run over the reversed signal.
9. **Window bounds**: in the BPM, offset and timeline code, `range(a, b)` is exclusive of `b` and the `min(i + k, n - 1) + 1` scans are inclusive. Copy them exactly. The ±10, ±30, ±0.7P and ±8 windows decide parity.
10. **Constants**: `22.5` (display offset), `6.2` (latency), `285.7142857142857`, `30`, `35` and the thresholds come from `ALGORITHM.md` section 7. Name them as constants.

## Audio decoding

- Packages: `ManagedBass` 4.0.2 (wrapper) and the natives from `ppy.osu.Framework.NativeLibs` **2025.806.0-nativelibs**, the version current osu.Framework uses. Its `runtimes/win-x64/native/bass.dll` is BASS 2.4.17 x64, and it also ships `bassmix.dll` and `bass_fx.dll`. The newest version without a suffix, 2022.525.0, ships the older BASS 2.4.16.
- Mirror the original:
  - `Bass.Init(0, 44100)`
  - `CreateStream(file, Decode | Prescan | Float)`
  - read all of it with `ChannelGetData`
  - mono = **sum** of the channels (not the average)
- **No 529-sample shim.** That shim only exists because the Python reference uses mpg123. BASS is the original's own decoder.
  - Check the three MP3s without a Xing/Info header in the parity set: Hayakore, lapix, Jamie. Their offsets show whether BASS 2.4.17 x64 decodes like 2.4.15 x86.
  - If they differ by a constant, document it in `ALGORITHM.md` before adding any correction.

## Golden data for stage tests

`tools/dump_golden.py <audio> <outdir>` runs the Python reference and writes:
- `mono.f64`: the decoded mono samples
- `rate.txt`
- `envelope.f64`: D
- `acf.f64`: first 2000 lags
- `result.json`: status, bpm, offset_int, flags and the marks string

C# stage tests **load `mono.f64` directly**, skipping decoding, so that only the DSP is compared. Tolerances:
- D: max abs diff ≤ 1e-9 · max|D|
- acf: relative 1e-9
- bpm and offset_int: |Δ| < 1e-6
- marks: equal

Generate golden data for at least Judgement (OGG) and Hayakore (MP3 without a header). `tests/golden/` is gitignored because it is large and can be regenerated.

The CLI output format must match `reference/timing_analyzer.py main()` exactly: the `Timeline   >>…<<` and `Time (min) >>…<<` lines appear only when flags != 0, followed by `BPM:    %8.3f` and `Offset: %8.0f`. Python's `%8.0f` rounds exact halves to even, but C# `ToString("F0")` rounds them away from zero. Use `Math.Round(value, MidpointRounding.ToEven).ToString("F0", CultureInfo.InvariantCulture)`, padded to 8 characters. Exact `.5` offsets do not occur in practice. How the original VS2010 CRT breaks ties has not been verified.

**Always format numbers with `CultureInfo.InvariantCulture`.** This machine runs th-TH with the Buddhist calendar, and that already broke StreamCompanion's version stamp.

## Guardrails

- Never change `reference/`, `reverse/` or the Python parity results to make C# pass. The reference is the spec.
- When a parity case fails, first compare stage by stage against the golden data. Do not change thresholds.
- Commit after each green task. End commit messages with the executor's co-author line.
- Escalate (to the planner) with the failing stage diff if the same mismatch survives two fix attempts.
